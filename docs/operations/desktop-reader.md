# 設定 Windows 桌面讀卡端

桌面端可裝在任一可連到後端、且接有實體感應讀卡機的 Windows 電腦。Windows 包須保留整個 `reader_client/` 資料夾，入口是 `reader_client/reader_client_app.exe`。裝置身分保存在該 Windows 使用者的 `%LOCALAPPDATA%\CVTAClockIn\device.json`；換版本時保留同機憑證，不要把檔案複製到另一台電腦。

## 安裝與核准

1. 接上讀卡機並確認 Windows 可辨識。將完整桌面端資料夾放在預定位置，啟動 `reader_client_app.exe`，確認通知區出現托盤圖示。
2. 從托盤選單選「設定伺服器位址」，輸入完整 URL，例如 `http://192.168.100.23:16688`。複製托盤選單顯示的「裝置 UUID」，不要傳送 `device.json` 或其中的密鑰。
3. 管理員登入管理頁，開啟「系統管理 → 讀卡端管理」，按「重新整理」，以 UUID 核對待審裝置，必要時命名，再按「核准」。連線正常時裝置約每 5 秒同步一次；網路連線失敗時仍約每 5 秒重試；註冊或簽章驗證失敗時約 30 秒後重試。打卡請求先恢復成功時會提前同步。可稍後重整確認狀態為「已核准」。
4. 用已綁定的卡測試一次打卡，於管理頁核對該員工的紀錄與時間。若要新增空卡，管理員在「卡片管理 → 新增卡片」選擇此讀卡端並發送命令；待桌面通知顯示加卡模式後，30 秒內刷一張卡。首次刷卡或逾時後會自動回到打卡模式；桌面通知與管理頁會回報新增成功、卡號已存在、逾時或失敗。若通知顯示結果未確認，請在管理頁重試查詢並核對卡片清單。加卡刷卡不會寫入離線打卡紀錄。

## 校正卡號順序

更換讀卡機、沿用既有卡號，或實卡打卡查不到正確員工時，可在一般模式從托盤選「校正卡號順序」，不需要 `--dev-mode`。先在管理頁查同一張實卡既有的 UID，輸入 8、14 或 20 位十六進位字元，然後在 60 秒內刷該卡。程式會比較讀卡機原始順序與位元組倒序；顯示 `UID MATCH` 後保存匹配順序，才可正式打卡。校正刷卡不會送出打卡或離線紀錄，也不會當成新增卡片。若以 `--dev-mode` 啟動，也可在等待校正刷卡時選「測試模式 → 模擬讀卡」，輸入模擬讀卡機的**原始 UID** 完成同一校正流程。

若顯示 `UID MISMATCH` 或逾時，讀卡端會停止處理打卡與新增卡片；請核對實卡及既有 UID，重新執行校正。校正結果保存在本機裝置設定中，重啟後仍有效。首次安裝或升級時，未校正的既有裝置沿用原桌面端的倒序處理方式。

## 測試模式與模擬讀卡

一般啟動時不顯示測試模式，也不能使用模擬讀卡。沒有實體讀卡機且需要測試時，先退出程式，再以 `reader_client_app.exe --dev-mode` 啟動；從原始碼執行則用 `python reader_client.py --dev-mode`。此時托盤選單才會出現「測試模式 → 模擬讀卡」。平常輸入視窗中的卡號是桌面讀卡程式處理後、與管理頁卡片資料相同的 UID；不要輸入讀卡機原始按鍵順序。只有在等待校正刷卡時，視窗會改為要求原始 UID，並將輸入交給校正比對，不會送出打卡或加卡請求。取消或留空不會送出。要關閉測試模式，退出程式後不帶參數重新啟動。程式由遠端指令重啟時會保留目前的啟動模式。

模擬讀卡與實卡共用同一條處理路徑：裝置須已核准且未暫停；一般模式會送出已簽章的打卡請求，成功後寫入正式考勤紀錄，網路故障時可能進入離線補送。若管理員已下達加卡命令且正在 30 秒加卡模式，模擬輸入會當作第一張卡送出加卡請求。測試前先告知管理員，使用測試卡號，並到管理頁核對結果。

## 更新或更換電腦

- 同一台電腦更新程式時，先退出舊程式，保留該使用者的 `device.json` 與[離線紀錄](offline.md)，再更換完整程式資料夾並重新測試。
- 換到另一台電腦時，讓新端自行產生 UUID 與密鑰，照上列步驟重新核准；不可複製舊機憑證。舊機若仍有待補送紀錄，先處理後再停用或撤銷舊裝置。

**完成標準：**後台顯示正確 UUID 且已核准，實卡測試紀錄已寫入。若讀卡端被暫停、停用或撤銷，先在後台確認狀態；撤銷不可直接恢復，詳見[裝置協定](https://github.com/CVTA-Engineers/CVTA-Attendance-System/blob/master/docs/DEPLOYMENT_AND_PROTOCOL.md)。
