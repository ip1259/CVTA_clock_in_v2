# 啟停後端與確認服務

目前後端在 `192.168.100.23` 的 Windows 主機上，由 `startup` 帳號登入後自動啟動。現行 v0.2.1 Windows 包的入口是 `api_server/api_server_app.exe`，管理前端已包在同一資料夾的 `_internal/dist/`；不可只搬走 exe。後端預設監聽埠是 `16688`，實際值可能由環境變數覆寫。

## 第一次確認啟動位置

1. 以 `startup` 帳號登入集中伺服器，按 `Win + R`，輸入 `shell:startup`（沒有 `%`）。這會開啟該帳號的啟動資料夾；[Microsoft 說明](https://support.microsoft.com/en-gb/windows/experience/startup-boot/configure-startup-applications-in-windows?nochrome=true)也使用此指令。
2. 找到後端啟動捷徑，開啟內容，記下「目標」與「起始位置」。目標應指向後端 exe；「起始位置」就是接下來尋找 `data/` 與 `logs/` 的第一個位置。若與實際執行位置不符，先查目前程序如何啟動，不要直接搬動資料庫。
3. 在「起始位置」確認 `data/punch_hot.db` 與 `logs/`；若沒有，停止變更並找到實際工作目錄。將目標、起始位置、主機名稱與監聽埠寫入維運紀錄。

## 停止與重新啟動

1. 通知現場暫停刷卡，記錄各讀卡端尚未補送的筆數。若要備份或還原，接著依[備份與還原](backup.md)操作。
2. 關閉目前後端程序並確認 `api_server_app.exe` 已結束。若由可見命令視窗啟動，可在該視窗正常中止；若沒有視窗，先辨認正確程序再於工作管理員結束，避免誤關其他程式。
3. 以原捷徑或相同的目標與起始位置重新啟動。不要把「起始位置」改成任意目錄；程式使用相對路徑存取資料庫與日誌。
4. 在可連線的電腦開啟 `http://192.168.100.23:16688/`，確認管理頁能載入、管理員能登入，並能查到原有員工或近期紀錄。若頁面載入失敗，先查程序、監聽埠、`api_server/_internal/dist/` 及工作目錄的 `logs/`。

**完成標準：**後端程序正常運行，管理頁可登入且舊資料可查。若登入頁能開但資料是空的，優先核對啟動工作目錄與 `data/punch_hot.db`，不要立即建立新資料或覆蓋檔案。
