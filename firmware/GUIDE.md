# NodeMCU-32S 獨立 RFID 讀卡器

韌體位於 [`CVTA_Reader/CVTA_Reader.ino`](CVTA_Reader/CVTA_Reader.ino)。它沿用主專案的裝置 API，不需要修改後端。刷卡時間採台灣時間（UTC+8）；1.44 吋 TFT 顯示英文短訊息與時間。

## 材料與接線

使用原 NodeMCU-32S 相容 ESP32 開發板與 Arduino IDE 環境、MFRC522／RC522（13.56 MHz），顯示器改為廣華電子 [LCD-144SPI 1.44 吋 SPI TFT 模組](https://shop.cpu.com.tw/product/56857/info/)（128 × 128）。正式韌體使用這片實物適用的 ILI9163 相容初始化序列；賣場規格標示 ST7735，詳細判斷見[實測結果](TEST_RESULTS.md)。移除原 LCD1602A、PCF8574 I²C 背板及其 I²C 電位轉換模組。另備 100 µF／16 V 電解電容及 0.1 µF／50 V 陶瓷電容各一顆。

| RC522 | NodeMCU-32S |
| --- | --- |
| 3.3V | 3V3 |
| GND | GND |
| SCK | GPIO18 |
| MISO | GPIO19 |
| MOSI | GPIO23 |
| SDA／SS | GPIO25 |
| RST | GPIO27 |
| IRQ | 不接 |

| TFT 背面排針（照片左至右） | NodeMCU-32S | 用途 |
| --- | --- | --- |
| LED | 3V3 | 常亮背光 |
| SCK | GPIO18 | 與 RC522 共用 SPI 時鐘 |
| SDA | GPIO23 | 與 RC522 共用 SPI 資料輸出；此處不是 I²C SDA |
| AO（A0） | GPIO21 | TFT 資料／命令選擇 |
| RESET | GPIO22 | TFT 重置 |
| CS | GPIO26 | TFT 專用片選，不可與 RC522 的 GPIO25 短接 |
| GND | GND | 與 RC522 共地 |
| VCC | 3V3 | 模組電源 |

RC522 接線維持原樣；其 MISO 仍接 GPIO19，TFT 沒有 MISO。**RC522 與 TFT 的電源及訊號皆使用 3.3 V，不接 5 V。**照片確認排針標示與順序；賣場規格標示 ST7735，但 PCB 外觀不能單獨證實控制器型號。SPI 線盡量短，兩個片選腳分開；若測試畫面持續出現條紋，先單獨測 TFT 並量測其 VCC 對 GND 電壓。

正式韌體採用 20 MHz SPI 區塊傳送；狀態文字先繪製在記憶體畫布，再一次送出。更換不同批次模組時，先使用[測試程式](TESTING.md)重新確認控制器與可視區。

畫面狀態使用放大的英文文字和背景色：READY 黑底、已保存或完成的打卡綠底、阻擋打卡的錯誤紅底；`OFFLINE SAVED` 為深琥珀底，表示已存入本機但仍待伺服器確認。文字仍直接顯示狀態，不只靠顏色辨識。成功畫面顯示約 3 秒後回到 READY。

在 **RC522 模組的 3.3V 與 GND 腳附近**並聯 100 µF／16 V 電解電容及 0.1 µF／50 V 陶瓷電容，縮短到模組的連線。電解電容正極接 3.3V、負極接 GND；陶瓷電容無極性。這兩顆是電源緩衝與高頻去耦，用於改善可能的瞬間壓降與雜訊；不能替代足夠的 3.3 V 供電能力。通電前確認極性及 3.3V／GND 間沒有短路。

## Arduino IDE

請依 [`BUILD.md`](BUILD.md) 安裝依賴、選擇板型、編譯及燒錄。首次燒錄後以 **115200 baud** 開啟序列監控器，行尾選 **Newline**，執行 `selftest`，應輸出 `Protocol self-test PASS`。

## 設定與啟用

可在 USB 序列監控器或 BLE 終端輸入以下相同命令。設定會保存，之後可再次修改：

```text
wifi <YOUR WIFI SSID> <YOUR WIFI PassWord>
server http://<打卡伺服器IP>:<打卡伺服器PORT, 預設16688>
name <設備名稱可自訂>
status
```

`wifi` 的 SSID 不支援空格。`server` 僅接受受信任內網的 `http://主機:埠`，不含路徑；改變伺服器位址後會重新檢查註冊與核准狀態。序列埠輸入不遮蔽密碼，請在可信任電腦上操作；韌體不會回印密碼或裝置密鑰。Wi‑Fi 須能連到後端及 NTP 服務。每次開機都必須取得 NTP 時間，之後持續通電斷網最多接受 24 小時的離線打卡。

### BLE 設定連線

使用支援 BLE GATT UART 的終端程式（Android、iPhone／iPad 或 Windows 均可），搜尋名稱 `CVTA-<UUID 前 8 碼>`。這是 **BLE**，不會出現傳統藍牙 SPP／COM 埠。連線時 TFT 顯示 `BLE PAIR` 與六位數配對碼；在手機或電腦的配對提示輸入該碼。BLE 使用需配對且加密的特徵值，接收端會阻擋未配對的設定寫入；已配對裝置重新連線通常會沿用已儲存的金鑰。請在可信任的現場配對，勿把配對碼拍照或傳給他人。

終端使用 Nordic UART Service（NUS）：服務 `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`，將文字以 **Write with response** 寫到 RX `6E400002-B5A3-F393-E0A9-E50E24DCCA9E`，訂閱 TX `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` 的 **Notify** 查看回覆。輸入框只打 `help`、`status` 等指令文字；行尾選 **LF** 或 **CRLF**，不要把反斜線與字母 r／n 當成文字輸入。每條指令需以實際換行字元結束；長指令可分段寫入，總長最多 220 字元。先送 `help` 和 `status`，確認回覆後再設定 `wifi`、`server`、`name`。`calibrate` 後刷卡時，UID 及比對結果也會從 TX 回傳。BLE 終端可能保留輸入紀錄，輸入 Wi‑Fi 密碼後請清除該程式的歷史紀錄。

首次連上後，裝置會以序列埠 `status` 所示 UUID 向後端申請。管理員於「系統設定與管理 → 讀卡端管理」核對並核准；`poll` 可立即查詢狀態。Wi‑Fi 連上或 NTP 首次校時完成後會立即查詢；連線正常時約每 5 秒自動輪詢，伺服器無回應或驗證失敗時改為約 30 秒重試，避免讀卡迴圈反覆被網路逾時阻塞。待審、暫停、停用、撤銷時不接受打卡。

### 遠端新增空卡

管理員在管理頁「卡片管理 → 新增卡片」選擇本機並發送命令。等待 TFT 顯示 `ADD CARD`，在 30 秒內刷一張卡。首次刷卡或逾時會自動回到打卡模式；新增卡片不進入 LittleFS 離線打卡佇列，TFT 依已驗證簽章的伺服器回應顯示 `CARD ADDED`（成功）、`CARD EXISTS`（卡號已存在）、`ADD FAILED`（伺服器拒絕）、`ADD UNKNOWN`（回應無法確認）或 `ADD TIMEOUT`（30 秒內未刷卡）。管理頁也會顯示結果；看到 `ADD UNKNOWN` 時請先到管理頁查詢並核對卡片清單。須先核准裝置並用既有卡完成 `calibrate`；斷線、暫停或失去核准會結束加卡模式。

### 校對既有卡號

先在舊讀卡端或後台查得**同一張實卡**的既有 8 位 UID，然後輸入：

```text
calibrate A1B2C3D4
```

60 秒內拿該卡刷 RC522。韌體會顯示 RC522 原始 UID 與位元組倒序 UID，並保存與既有 UID 相符的順序。顯示 `UID MATCH` 才能啟用打卡；`UID MISMATCH` 時不要重新綁卡，先檢查是否拿錯卡、卡片頻率或舊讀卡器輸出格式。可隨時重新執行 `calibrate`。校對支援 4、7 或 10 位元組 UID；既有資料庫的卡號目前均為 4 位元組的 8 位十六進位字元。

## 離線佇列與狀態

刷卡先寫入 LittleFS，每筆一個檔案，上限 256 筆，然後送往 `/api/v1/punch`。網路中斷時 TFT 顯示 `OFFLINE SAVED`；恢復連線後依序補送。只有收到**驗證通過簽章**的 HTTP 200 回應才刪除本地事件。400／404 事件改存 `.bad` 等待人工處理；401／403 停止補送並要求檢查裝置狀態。若已入庫但回應遺失，重送仍可能造成重複打卡，這是現有 API 的已接受限制。

| 序列埠命令 | 用途 |
| --- | --- |
| `help` | 列出命令 |
| `status` | UUID、連線、核准、時間與佇列摘要；不顯示密鑰 |
| `queue` | 查看佇列數與最舊待送 ID |
| `bad` | 列出永久錯誤事件的 UID 與時間 |
| `discard-bad 123` | 人工確認後刪除指定 `.bad` 事件 |
| `poll` | 立即查詢裝置狀態 |
| `selftest` | 驗證 SHA-256／HMAC 實作 |

`SAVED` 表示事件已保存、正等待伺服器確認；`OK` 才表示伺服器已接受。`QUEUE FULL/ERR` 表示**這次打卡未保存**，需人工處理。`TIME UNSYNC` 表示開機後尚未校時，或最後一次校時超過 24 小時；此時不接受刷卡。`DENIED` 表示裝置未獲准或已暫停。

更換板型、分割區配置或清除快閃記憶體前，先確認 `queue` 無待補送事件；清除快閃記憶體也會失去裝置 UUID 與密鑰，之後需要重新申請核准。
