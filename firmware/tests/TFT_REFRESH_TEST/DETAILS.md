# TFT 更新速度測試

這支測試由 **1 MHz、逐位元組傳送**起，逐步比較較高 SPI 時鐘與區塊傳送。只需 ESP32 Arduino 核心，不需額外顯示函式庫。請先拔除 RC522；TFT 接線與 `TFT_LCD_TEST` 相同。開啟 `TFT_REFRESH_TEST.ino`，選 NodeMCU-32S，序列監控器設 115200 baud。

開機會在 1 MHz 逐位元組模式顯示圖案並輸出全畫面 `full`、中間 128×76 區域 `partial` 的耗時（微秒）。畫面應有白色橫帶，帶內上排紅／綠、下排藍／黑四塊；外圍底色每次測試會在黑與洋紅間交替，應與序列訊息相符。每次換速後，**等該次序列結果出現，再檢查畫面完整且穩定**。序列印出的 `transfer fps` 只是全畫面傳輸速度換算，不是 LCD 本身的掃描刷新率。

| 命令 | 功能 |
| --- | --- |
| `n` | 下一級 SPI 時鐘：1、2、4、8、12、16、20、26、40 MHz |
| `b` | 回到前一級 |
| `f` | 在逐位元組與 512 位元組區塊傳送之間切換 |
| `t` | 重測目前設定 |
| `1` | 回到 1 MHz，重新初始化並重畫 |

建議先保持逐位元組模式，逐級送 `n`，記下**最高能完整顯示四塊、外圍底色每次跟著切換，且無條紋、閃爍的速度**；回到 1 MHz 後送 `f` 啟用區塊傳送，再逐級測一次。若高速下畫面異常，送 `1` 可在已知可用的 1 MHz 下重新初始化。序列顯示的是要求的 SPI 時鐘，實際時鐘可能由 ESP32 分頻。請回報每一組的 `full`、`partial` 時間與最高正常時鐘；正式韌體應取低於失效點、且與 RC522 共用時仍可靠的設定。
