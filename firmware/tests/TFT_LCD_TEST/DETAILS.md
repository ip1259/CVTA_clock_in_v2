# TFT LCD 測試

此程式使用與正式 `CVTA_Reader` 相同的 ILI9163 相容顯示驅動，以 20 MHz 硬體 SPI 和區塊傳送顯示文字、外框和紅／綠／藍色塊。需安裝 **Adafruit GFX Library**；`ILI9163Display.h` 與 `ReaderStatusDisplay.h` 已隨測試程式附上，Arduino IDE 開啟 `.ino` 時應保持三個檔案在同一資料夾。

先拔除 RC522，TFT 的 `LED/VCC → 3V3`、`GND → GND`、`SCK → GPIO18`、`SDA → GPIO23`、`AO/A0 → GPIO21`、`RESET → GPIO22`、`CS → GPIO26`。在 Arduino IDE 選 NodeMCU-32S，燒錄 `TFT_LCD_TEST.ino`，序列監控器設 115200 baud。

開機後應看到白框、`ESP32`、`ILI9163 TEST` 及三個紅／綠／藍色塊。序列命令 `p` 重畫圖案，`r/g/b/k/w` 填滿紅／綠／藍／黑／白。若圖案缺邊或顏色異常，可用[控制器診斷測試](../TFT_CONTROLLER_TEST/README.md)重測控制器記憶體偏移與 SPI 模式。

### 更換模組後校正畫面位置

測試程式初始使用舊模組方向 `0`、偏移 `(column=0, row=32)`。序列監控器行尾選 **Newline**。若文字上下顛倒，先輸入 `m 3` 測試旋轉 180°；若文字的左右仍正確、只有上下鏡像，試 `m 2`。`m 0` 為原方向、`m 1` 為左右鏡像。每次指令都會重畫圖案；看 `ESP32` 文字和四角色塊的位置，不要只看對稱的白框。

方向正確後再調整偏移。若畫面整體位移或白框缺邊，輸入 `o 0 0` 測試另一種 128 × 128 可視區起點；也可輸入 `o 2 3` 等數值逐步微調。格式是 `o <column> <row>`，兩值皆為控制器記憶體起點，範圍 0–128。以白框四邊與四個不同顏色的角塊都完整可見、位置對齊為準，再輸入 `s` 與 `c` 檢查狀態及時鐘文字。上述命令只在測試程式執行期間生效，**不儲存到裝置**。若仍有舊圖案殘留，可斷電重啟後直接輸入候選值再看。

記下實測的方向模式與 `(column, row)`，依[編譯與燒錄指南](../../BUILD.md)燒錄正式韌體後，在 USB 或已配對的 BLE 終端輸入相同的 `m`、`o` 指令，再用 `display` 核對。成功的設定會保存在裝置內；重啟後再次確認。這些設定只影響 TFT，不需清除快閃記憶體或重新註冊裝置。若所有模式與偏移值都無法讓圖案對齊，或顏色異常，先用[控制器診斷測試](../TFT_CONTROLLER_TEST/README.md)核對控制器初始化，再確認模組的解析度與接線。

送 `c` 可模擬正式韌體的每秒時間更新：先在記憶體畫好 `READY` 與時間，再一次送至顯示器。序列輸出每次區域傳送的微秒數。請觀察時間是否仍明顯閃爍；送 `p` 可退出時鐘模式。

送 `s` 可依序預覽正式韌體的狀態畫面：READY 黑底、SAVED 暖黃底、OK／CARD ADDED 綠底、OFFLINE SAVED／CARD EXISTS／ADD UNKNOWN／PENDING／TIME UNSYNC 橘底、PUNCH ERROR／DENIED／STORAGE ERROR 紅底。每次送一次 `s` 切換下一個狀態；長狀態會分成兩行顯示。紅色錯誤畫面有白框，讓辨識不只依賴顏色。請確認暖黃與警告橘色明顯不同，每個畫面的字沒有被裁切，白色字在各背景上清楚，且換色後沒有殘留上一個畫面。

這塊實物的畫面與正式韌體觀察見[實測結果](../../TEST_RESULTS.md)。

若畫面正確但更新較慢，可用[更新速度測試](../TFT_REFRESH_TEST/README.md)量測不同 SPI 時鐘與區塊傳送的效果。
